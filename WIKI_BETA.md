# CrossPoint 1.6.0 + Wiki — original X4 beta 1

This branch adds an offline Wiki activity to CrossPoint's own home screen. It is
not a dualboot bundle, not Microreader, and not an official CrossPoint release.
A successfully completed `X4 Wiki beta` build produces an application-only
ESP32-C3 `.bin`. Hardware operation and installation/recovery on your particular
X4 have NOT been verified. A green build is not a hardware certification.

## Data on the SD card

The firmware does not contain the encyclopedia. Use the published Almanac
Simple English Wikipedia WCDB data pack from this exact release:

https://github.com/Sparkadium/crosspoint-reader-almanac/releases/download/v1.1.0-almanac/wikipedia.cdb

Source release: https://github.com/Sparkadium/crosspoint-reader-almanac/releases/tag/v1.1.0-almanac

Expected size: 48,523,777 bytes.
SHA-256: `c994f024322352de9e8ec96092834b2296f2304400337a016dc7a8eedf0e2b30`.
The build's host tests download and check that exact pack. It is provided by
Sparkadium, not generated by this project. Wikipedia content is attributed to
Simple English Wikipedia contributors and retains its applicable CC BY-SA
terms; follow the source release and Wikipedia licensing information. The
firmware's MIT license does not replace the content license.

Copy the downloaded file, named `wikipedia.cdb`, to the SD card's top level.
`/Wikipedia/wikipedia.cdb` is also accepted. The top-level file takes priority.
Do not rename a `.zim`, EPUB, or unrelated CDB database to this filename: that
does not convert it. Only the WCDB layout described below is implemented.

## Controls

Open **Wiki** on CrossPoint's home screen. Normal CrossPoint book reading,
settings, file transfer and file browsing remain separate and available.

- Front Back/Home: return to CrossPoint Home. Hold it: cycle three text sizes.
- Front Confirm/Search: enter an article title. An exact match is preferred;
  otherwise the first prefix match is opened. Hold it: random article.
- Front Left/Right (Prev/Next): previous/next encyclopedia entry.
- Side Up/Down: previous/next page within the current article.

Shortcuts follow CrossPoint's mapped logical buttons. A trailing key release
from the keyboard is ignored. When a theme cannot fit all home menu rows, the
menu window follows the selected item rather than hiding the last actions.
Font size is retained. This beta does not promise saved article position after
sleep/restart or global article history.

## Deliberate beta limits

Text-only WCDB, no images, no native ZIM, no live Wikipedia downloads, no full-
text search, no selectable in-article links. ASCII title case folding is
supported; non-ASCII UTF-8 bytes compare literally. Raw DEFLATE blocks must be
at most 32 KiB. The reader cannot recover article material that was shortened
when a data pack was created. The first-prefix search is not a results-list UI.
Random selection is by block then entry, not a uniform sample of all titles.

The two large archive buffers have fixed ceilings and checked, nonthrowing
allocation. Index records remain on the SD card. Text layout keeps one line
and page byte offsets rather than a second complete copy of a wrapped article.
Other CrossPoint and C++ string allocations still use the existing firmware
memory model; real peak heap, power usage, typography and button responsiveness
need device testing. The file-size/index checks do not authenticate content.

## Installation boundary

The candidate is named `crosspoint-1.6.0-wiki-beta1-x4-UNTESTED.bin`.
It is an **application image**, not a complete flash dump. Do not write it at
address zero. No bootloader, boot-selection data, partition image or other
uploaded firmware has been merged into it. Not for the ESP32-S3 X4 Pro/X4C.

Before installing, back up your SD card and device configuration and establish
your X4's USB-lock/recovery status and installed partition layout. Do not install
experimental firmware on a USB-locked device without a verified recovery path.
A dualboot device may not have the layout assumed by a standard installer.
Do not erase flash or overwrite partitions based only on the candidate passing
its image checks. This package intentionally contains no automatic flashing
command. Use a compatible application-update path only after those checks.

## Build and verification

Base: CrossPoint 1.6.0 commit `54337e6d73fc628f4ba523ddc89a743ca8c6e4c5`.
The separate `wiki-x4-beta` branch leaves the fork's `develop` branch untouched.
The integration script refuses unknown base files and applies the small home-
menu changes before compilation. Complete changed source is in the branch;
generated home sources are included in the successful build artifact.

The workflow runs:

1. Guarded menu integration on a full recursive checkout.
2. Compiled `WikiArchive.cpp` tests with host storage/Arduino/zlib adapters,
   AddressSanitizer and UndefinedBehaviorSanitizer; then the published pack.
3. The actual ESP32-C3 PlatformIO build (`wiki_x4_beta`).
4. Application descriptor, chip, length, checksum, appended SHA-256, partition
   MD5 and application-slot size checks, plus official esptool image-info.

Only successful compilation and validation publish a firmware candidate.
Host zlib tests are not tests of the on-device uzlib decoder or the display.
A build log, data-pack report, dependency list and manifest accompany the image.

Developer reproduction on a clean checkout: install the dependencies in
`.github/workflows/wiki-x4-beta.yml`, run `python scripts/wiki_integrate.py`,
`python scripts/wiki_host_tests.py`, `pio run -e wiki_x4_beta`, then
`python scripts/wiki_package.py`. The integration step is intentionally not
silently idempotent: repeat from a clean checkout rather than patching twice.
